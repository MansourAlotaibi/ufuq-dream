# Contributing

Keep the core offline, Arabic-first, Saudi-specific, D-pad accessible and lightweight on API 28 / 2 GB devices. Prefer focused changes to the current native Views architecture. No mandatory accounts, ads, analytics or large framework migrations.

1. Open an issue describing the visible problem and affected TV/API level. Remove private IPs, custom greetings, account details and unrestricted logs.
2. Build and run lint, unit tests and the public asset gate. Host tests do not replace TV acceptance.
3. For behavior changes, document preference migration, Save/Cancel, preview/Dream consistency and lifecycle cleanup. Use a debug build on an explicitly authorized test device. Never clear user data to hide a migration defect.
4. Include screenshots for visual changes (identify host renders versus physical TV captures), and check all three palettes, overscan and long Arabic strings.
5. Do not commit personal videos, signing keys, SDK paths or device dumps. Media contributions require creator/source/license/location, modification history and SHA256; no social-media reuploads or stock previews. CC BY-SA derivatives retain their licenses.

Code contributions are under MIT; media is reviewed under its own license. Discuss large features before implementation. Public distribution of the private test video is not authorized by this repository.
