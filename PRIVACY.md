# Privacy

Ufuq Dream's application requests the normal INTERNET and ACCESS_NETWORK_STATE permissions for optional smart information and includes no advertising, analytics, account or third-party networking SDK. It does not send greetings,usage or local media to a server. Optional saved weather/prayer selections send only the chosen city-centre coordinates and necessary calculation parameters to their providers,as detailed below.

Preferences (including custom greeting text) and user-selected videos and generated local posters are stored in app-private internal storage. The current app disables Android backup through its manifest; manufacturer-specific transfer behavior has not been certified. Uninstalling removes app-private data. There is no in-app cloud sync or export.

Photo credit links are displayed as text; the app does not fetch their contents. Android Studio/Gradle use the network to obtain development dependencies; this is separate from runtime behavior. Debug builds can emit decoder state/error logs for development. Do not post unrestricted logcat or preference backups in public issues.

The GitHub project and other external services have their own privacy policies. No claim of universal behavior across all Android TV vendors is made.

The scoped Android document picker grants access only to the selected video. The app copies it internally and does not retain a persistent URI grant or request broad storage access. Import does not publish or upload the file. The original selected file is not edited. A document provider may independently use network access. See docs/LOCAL-VIDEO.md.

## 0.9 development: optional smart information
The stability candidate additionally requests normal ACCESS_NETWORK_STATE to avoid attempts while offline. It does not grant location or Wi-Fi credential access. Active-only connectivity callbacks are removed on stop. Sanitized private diagnostics retain provider,status category,HTTP code and time,not exception messages,IP addresses or media paths.

Both prayer and weather widgets default off and are staged until Save. Prayer offers AlAdhan HTTPS or an explicitly selected offline calculation. Existing development preferences that used offline calculation retain that source. Online prayer requests to api.aladhan.com include city-centre coordinates, date, timezone, calculation method and Asr school; the provider also sees IP address. Source: https://aladhan.com/prayer-times-api . Rolling calendars contain30 exact Gregorian dates,validated and committed as one snapshot,with at most3 city/method/school configurations. Existing bounded daily caches remain readable for migration. Covered dates work offline; refresh starts below7 remaining days. Online errors never silently substitute offline prayer times. Weather uses HTTPS requests directly to api.open-meteo.com only while the Dream/Studio is visible and the selected city was previously saved as enabled. The provider necessarily receives IP address and the selected city-centre coordinates,not a measured device location. Provider policies: https://open-meteo.com/en/terms . No location permission,accounts,API keys,analytics,ad SDK,background tracking or hidden polling is added. City selection/C/F are local preferences; latest weather is cached in app-private preferences. Disabling a network widget stops new requests; canceled in-flight I/O can take finite time to unwind. Staged city/toggle/method changes do not silently grant network consent. Weather and prayer values are never fabricated as sample/live data. Staged previews show valid cached values or a clear no-data message.


## 0.10 optional reading and favorite-team fixtures
The optional Quran/Hadith corpus is bundled and selected locally by device-local day; no download, account, analytics or network request. Religious text remains Arabic even with English UI; no machine translation is generated.

Favorite-team fixtures are opt-in and require the selected team to be saved. Foreground-only HTTPS to www.thesportsdb.com includes a catalog team ID/public test identifier and exposes the ordinary client IP to that provider; no location/account/private key is sent. Parsed factual future fixtures are cached privately for at most8 teams, hourly successful refresh, bounded retries and24-hour maximum cached-feed age. No club artwork, scores or hidden inactive polling. Switching an unsaved team never grants network consent. No additional Android permission. Disabling/stopping cancels owned work/callbacks; native I/O may take finite timeout to unwind. Existing city/method/weather/media preferences remain independent. The underlying development build was accepted by the owner on Mi Box S. This does not certify other devices or every third-party endpoint. All optional network features remain off by default.

## 0.11 offline remembrance and occasions
Two traditional Arabic remembrance texts and their references are bundled locally. Optional occasion calculations use Android ICU and the device-local date/timezone. A custom occasion name and Gregorian date stay in app-private preferences and are never uploaded. The editor and preview are staged until Save. No new permission, provider, account, location request or background task is introduced. Football competition names use the existing response; kickoff countdowns are calculated locally without additional requests.

## 0.12 development: optional reading-library updates
Default off. After enabling and explicitly saving Library updates, a due visible Studio/Dream can make a conditional HTTPS GET to the official repository's raw GitHub content channel no more often than15 days after a successful check. Devices without validated internet do not request or advance the schedule. Failed requests back off1/3/7/15 days and honor bounded Retry-After. No background job, alarm, wake lock, new permission, account, location, tracking or ad SDK. GitHub necessarily receives ordinary client IP/request headers and a content ETag; no personal settings/media/city/team/greeting/custom occasion are sent. Signed reviewed text data are validated and written atomically to app-private storage; current/bundled text remains available offline. The bundled DER file is a public verification certificate only. The development channel remains unpublished until release approval.
