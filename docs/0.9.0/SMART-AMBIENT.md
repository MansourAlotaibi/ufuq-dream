# 0.9.0 Smart Ambient — development, not a stable release

The current public production release remains v0.8.3-rc1. See STABILIZATION.md for the owner's explicitly uncompleted recovery/physical-TV gates. This branch keeps com.ufuq.dream and API28, increments the development build to code16, and must not be installed on the accepted Mi Box without review and explicit authorization.

## Implemented
- Optional offline five-prayer panel, city-local times, next prayer/countdown to minute precision, bounded8-day cache.
- Sixteen manually chosen city centres, Saudi cities first. No GPS/geocoding/location permission. City/timezone identifiers are fixed local facts, not a user's measured location.
- Umm al-Qura calculation convention: Fajr18.5°, Isha90minutes after Maghrib,120minutes in calculated Ramadan via Android ICU Umm al-Qura. Standard Asr by default; optional Hanafi Asr. Optional MWL(Fajr18°/Isha17°).
- Pinned Adhan Java1.2.1(MIT,Batoul Apps) for solar mathematics; no hand-written prayer astronomy or network dependency. Its legacy README mentions18°; the explicit18.5° override matches the published AlAdhan method4 parameters. This pin is a small dependency without transitive runtime libraries; it is not a claim to use the newest Kotlin rewrite.
- Reference tests against3 published AlAdhan computed schedules(Riyadh/Makkah Nov2,2026;Jeddah Mar15,2026) within3minutes; factual fixtures,source URLs,response checksums and retrieval dates retained in prayer-reference.json. **Not official Saudi/Mosque approval.** Ramadan dates,local horizons/elevation,rounding and actual sighting may differ. Display explicitly says calculated/not official; users must check their mosque's timetable.
- Optional weather: current model temperature,WMO condition,custom static icon,C/F,manual city,30/60/180minute refresh,model observation age,old-cache/failure/loading/no-data states. No embedded API keys.
- Open-Meteo free non-commercial endpoint, CC BY4.0 data with in-panel attribution and source/license URLs in app credits. Free nonprofit/no-ads app use is explicitly allowed by https://open-meteo.com/en/terms (checked2026-11-02). MIT code licensing does not grant commercial forks free commercial API access; they need an appropriate provider/service agreement. Data license and hosted API access terms are different.
- One request lease process-wide,city-specific monotonic attempt limits,64KiB response limit,finite8second connect/read timeouts,no redirect following,default TLS verification. At most one latest reading per fixed city in app-private preferences. Reject malformed/missing/out-of-range/future data,wrong units and observations older than48h. Older than3h is visibly stale. Transport failures retain the last valid reading. Cached Celsius is converted locally; switching units does not fetch.

## Consent and lifecycle
Both optional widgets default off for new and existing users. New smart_* keys are written only through the existing explicit Save transaction. Cancel/Back behavior and original preferences are unchanged.

Prayer preview uses real local calculations. Weather preview uses a labeled sample only when no selected-city cache exists and that city/feature is not already enabled in saved settings. A staged toggle/city change never authorizes a network request. Existing actual cached data is marked with age; saved opt-in allows fetch only while preview or Dream is active. No service,alarm,WorkManager,tracker or hidden polling exists. On pause/stop,the session cancels callbacks/work and prevents further requests. In-flight native HTTP may take up to its finite timeout to unwind; it never blocks the main thread. Cancellation/stale callbacks cannot release a newer token-owned request lease.

## Widget architecture and layout
Clock/date remain the established SceneRenderer adapter. WidgetRegistry records id,priority,placement slot,reserved height and independent enabled predicate. SmartLayout consumes enabled information-widget metadata to reserve a bottom safe band. ClockPlacement still applies Automatic or the chosen3x3 position in the remaining safe region; its saved value is never overwritten. With widgets disabled,the full original clock region is restored.

SmartPanel is the lightweight native presentation adapter for PrayerProvider and WeatherSession/WeatherCache. Models/providers/transport/placement are separate; adding a future renderer/provider goes through registry and panel adapters rather than rewriting DreamService or the background/video engine. There is no football or audio implementation/control. The registry is an extension point,not a plugin loader or a claim of dynamic third-party modules.

The same AmbientDisplay instance composition is used by the Dream and scaled Studio. Widget presentation updates at most once per minute/settings/result change,even with clock seconds enabled. Prayer labels/countdown and temperature use bidi isolation. Static backgrounds are not moved. Theme ink and optional night dimming apply to the panel. Safe-band reservation tests cover720p/1080p/4K and all9 manual placements plus Automatic. Native-view bounds are also checked at1080p; real overscan/readability still need TV review.

## Performance and limits
Existing current/next image caps and process-wide single video decoder are preserved. Weather parsing≤64KiB,stream buffer4KiB,prayer cache≤8days,weather disk cache≤16city readings. No new heavy UI,network or location SDK. Native weather icons reuse paint; one small icon is created on a minute/settings/result update. HTTP is worker-only,background images retain1080p maximum,Studio640px decode cap.

Runtime PSS,CPU,GPU,thermal,decoder,sleep/wake and overnight stability are **not measured on physical hardware for0.9**. Host screenshots and Robolectric tests are not proof of them. Document-picker availability and native import/decoder limitations from RC remain. High-latitude schedules use library fallback rules and are not independently certified. A wrong device clock can invalidate weather freshness; invalid data fails closed. Signing recovery helper is owner-run and has not been used to verify an independent backup.
